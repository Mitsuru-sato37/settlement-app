# Settlement App Mock Design

## Goal

仲間内のゲームや食事の立替を、スマホで素早く入力して見やすく精算できる Native 方式の React モックアプリを作る。

## Scope

- 通常精算、支払い内訳ごとの対象者切替、ポーカー、麻雀、ノリ打ち、全額払いルーレットの6つの主要機能（ナビゲーション上は5モード、対象者切替は通常精算内）。
- データはローカルの型付きモックデータのみ。バックエンド、認証、永続化は対象外。
- 画面はサイドナビ付きのデスクトップ幅とスマホ幅に対応するレスポンシブ UI。
- 金額計算は共通の純粋関数としてテスト可能にする。

## UX

- ダークネイビーを基調に、サンセットオレンジを主要アクションに使う。
- 左のモードナビで精算方法を切り替え、上部にタイトル・参加者・合計を表示。
- 入力画面は「概要 → 明細 → 結果」の流れを1画面内で理解できるカード構成。
- 支払い明細には対象者チップを置き、クリックで対象者を切り替える。
- モード固有の入力はサマリーカードに変換し、最終的な受取/支払結果を共通の結果パネルに表示する。

## Data and behavior

- `Participant`, `ExpenseItem`, `Settlement`, `SettlementMode` を中心に型を定義する。
- 通常精算は明細単位の対象者数で均等割りする。
- 支払い内訳ごとの対象者切替は、対象者を変更すると均等割りの分母と結果が再計算される。
- ポーカー、麻雀、ノリ打ちは各ゲームの増減値を参加者ごとに入力したモックとして表示する。
- 全額払いルーレットは参加者の中から支払者を選び、全額を参加者数で割った金額を各自の負担として表示する。

## Non-goals

- 実際のルーレット乱数、外部 API、DB、アカウント、決済。
- 複数ページルーティングや本番向けアクセシビリティ監査。
