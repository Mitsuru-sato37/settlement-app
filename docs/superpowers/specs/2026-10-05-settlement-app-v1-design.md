# 仲間内精算アプリ 実用初版 設計

## 目的と前提

仲間内の立替・ゲーム収支を一人が入力し、同じ画面を見せながら「誰が誰に何円払うか」を確認できる実用初版にする。既存の React + TypeScript + Vite と明るい画面デザインを維持する。初版ではアカウント、共同編集、決済、サーバー同期、端末間共有は作らない。

記録は使った端末・ブラウザにだけ残ればよい。公開済み Sites は既存の非公開範囲を維持し、公開範囲の変更は別途明示的な依頼を要する。

## 採用する構成

型付きの精算記録をブラウザの `localStorage` にバージョン付きで保存する。各記録は一つのモードに属し、タイトル、参加者、入力、作成・更新日時を持つ。モードを切り替えても他モードの参加者や入力を流用しない。記録一覧から新規作成・切替・削除ができる。新規記録は空の入力から始め、既存のモック値は明示的に読み込むサンプルとして分離する。

候補は (1) `localStorage`、(2) IndexedDB、(3) サーバー保存。初版の少量の精算データと単一ブラウザ利用には (1) が最小で十分。ブラウザデータ消去に備え、全記録の JSON 書き出しと読み込みを用意する。将来の移行に備えて保存形式に `schemaVersion` を含める。

## データと責務

- `domain/model`: `SettlementCase` をモード別の判別可能な型として定義する。参加者 ID は記録内で一意、明細・半荘の ID も記録内で一意にする。
- `domain/settlement`: 金額・点数・割合の計算と入力検証を副作用のない関数に分離する。UI と保存処理は計算式を持たない。
- `storage`: 保存形式の検証、読み込み、保存、JSON 書き出し・読み込みを担当する。保存できなかった状態を UI に返す。
- `components` と各モード画面: 入力、エラー、収支、支払いの流れを表示する。巨大な `App.tsx` は記録管理と画面ルーティングを中心に整理する。

金額は円の整数、点数・枚数・割合の入力は有限数として検証する。計算結果に `NaN` や無限大を出さない。入力途中の無効な文字列はフォーム内に保持してエラーを表示し、有効値になるまで計算・保存値へ反映しない。参加者や支払者の参照が壊れる削除・読み込みは黙って補正せず、入力の修正を促す。削除と JSON 読み込みによる上書きには確認を付ける。

## 画面と計算

### 共通

記録ごとに参加者を追加・改名・削除できる。削除時は確認を出す。通常精算でその人が支払者なら明細の支払者を先に変更する。ポーカー・ノリ打ち・ルーレットでは該当する入力行も消えることを示し、麻雀ではその人が参加する半荘の席を先に変更する。結果には各人の受取・支払額と具体的な送金先・金額を表示する。収支が不一致または入力が無効な場合は理由と差額を表示し、確定した送金指示として見せない。保存状態は実際の書き込み成否を表示し、「自動保存済み」と偽らない。押しても動かない共有・編集・追加・ガイド等の操作は実装するか取り除く。

### 通常精算

明細の名称、金額、支払者、対象者を追加・編集・削除する。対象者が 0 人、支払者が存在しない、金額が負または整数でない明細はエラーとする。各明細は対象者で均等割りし、割り切れない 1 円単位の余りは参加者の表示順で配る。支払者の立替額から各自の負担額を差し引き、合計 0 円の収支から送金を組み立てる。合計金額、明細数、均等割り参考額は入力から算出し、固定値を表示しない。

### ポーカー

参加者ごとの最終収支を円で編集する。全員の合計が 0 円のときだけ送金を表示する。差額があるときは入力不足として差額を明示する。チップの購入・換金履歴までは初版の対象外とする。

### 麻雀

四麻と三麻の初期値を別にし、開始点、返し点、レート（1000 点当たりの円額）、オカ、順位ごとのウマ、チップの有無と 1 枚の円額を編集できる。半荘ごとに参加者を 3 人または 4 人選び、終局持ち点とチップ枚数を入力する。半荘は追加・削除でき、新しい半荘を上、古い半荘を下に並べる。現時点の累計を画面最上部に表示する。

各半荘で終局持ち点の合計が「開始点 × 人数」と一致するか確認する。順位は点数の降順、同点は入力順で決める。各人の点棒分は `(終局点数 - 返し点 + 該当順位のウマ + トップならオカ) × レート / 1000` 円とする。チップを含める場合は `(本人の枚数 - 参加者の平均枚数) × チップ価値` 円を足す。円未満の端数は参加者順の決定的な方法で処理し、妥当なゼロサム入力を丸め誤差だけで不一致にしない。設定や持ち点がゼロサムにならない場合は差額を示し、送金を確定表示しない。累計は半荘ごとの有効な結果の合計とし、未確定の半荘があれば累計も未確定とする。

### ノリ打ち

各人の投資額と回収額を入力する。全体損益 `回収合計 - 投資合計` を人数で均等割りし、送金用の各人の収支を `均等割り後の取り分 - (本人の回収額 - 投資額)` とする。余りの 1 円は参加者順で配り、送金総額の収支は必ず 0 円にする。投資・回収は 0 円以上の整数とし、均等以外の分配率は初版に設けない。

### 全額払いルーレット

各人の候補額を編集し、合計に占める割合を数値とホイールの面積で表示する。当選者が候補額の合計を全額支払う。合計 0 円では抽選できない。正の候補額を持つ人だけが当たり得る。抽選はブラウザの乱数を用い、表示と同じ候補額で重み付けする。ホイールの停止位置は選ばれた人の色の領域に一致させ、演出の途中では当選者を確定表示しない。候補額や参加者の変更後は古い当選結果を取り消す。動きを減らす OS 設定にも対応する。

## 保存・復旧・制約

- 変更は検証した保存形式で `localStorage` に自動保存し、再読み込み後も記録・入力・モードを復元する。保存不能（容量不足・ブラウザ設定等）は明示し、画面上の編集中データは保持する。
- JSON 書き出しは全記録と形式バージョンを含む。読み込みはサイズと構造を検証し、失敗時に既存データを変更しない。成功時のみ確認後に置き換える。
- サンプル値は実記録に自動混入させない。旧モックは永続データを持たないため、既存ブラウザからの自動移行対象はない。
- ローカル保存はバックアップや端末間同期ではない。消去・シークレットモード等で失われ得ることを UI と README に明記する。

## 検証とリリース条件

- 計算の単体テスト: 均等割りの余り、送金のゼロサム、ポーカー不一致、麻雀の三麻・四麻・複数半荘・不正な点数合計、ノリ打ちの損益均等化、ルーレットの確率区間と針の一致。
- 画面テスト: 全モードの入力変更、参加者の増減、記録の追加・切替・復元、無効入力、保存失敗、JSON 読み込み失敗。デスクトップとスマホ幅で主要操作の表示を確認する。
- `npm test`、型チェック、ビルド、差分チェックを通す。README を実装と一致させ、未実装の操作や虚偽の保存表示を残さない。
- 既存内容を壊さないよう差分を確認し、GitHub にコミット・Push した正確な状態を既存 Sites に非公開デプロイする。デプロイ成功を確認してから完了を報告する。
