## 入力、参加者、状態遷移

| 項目 | 状態 | 根拠 / 未確認範囲 |
| --- | --- | --- |
| 空/空白、負数、数字以外、小数 | PASS | 金額入力検証と保存形式検証、画面の不正入力テストあり |
| 長い/絵文字入り参加者名 | PASS | ブラウザー320pxで長い日本語・絵文字名を登録。参加者カード、収支、送金行で折返しを確認 |
| 長い費用名、多桁額 | PASS | ブラウザー320pxで長い費用名と10,001円を入力。対象B、支払A、送金B→A 10,001円を確認。入力欄内は長い文字列の一部が見切れるが入力値自体は保持 |
| 参加者追加のボタン二重クリック | PASS | 同名入力を素早く2回clickして参加者が1人だけ追加され、入力欄が空になった後のクリックが無視されることを確認 |
| 同じ表示名/同額費用の登録 | PARTIAL | UIは同名の人や、ラベル・金額が同一の明細を別IDとして許可する。仕様は参加者/明細IDの一意性を要求するが名前・内容の重複を禁止していないため、重複防止は追加しない。誤った二重課金と正当な同額費用を区別する入力仕様なし |
| 明細追加ボタン連打 | PARTIAL | 二重クリックで空の明細が2行追加される。クリックごとに明細を追加する既存動作であり、同額・同名明細の二重登録を抑止する仕様はない。内容を入力後の重複識別は未確認 |
| 参加者追加/削除前後の金額変更、支払者削除 | PARTIAL | 支払者/麻雀席参照中の削除抑止とポーカー入力行削除テストあり。入力順を全パターン組み合わせた画面試験は未実施 |
| 精算途中の条件変更、戻る、画面切替、入力途中の移動 | PARTIAL | roulette抽選中の状態保護、各画面の編集・記録切替・再読込テストあり。ブラウザー履歴による戻る操作は未確認 |
